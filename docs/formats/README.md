# File Format Documentation

This directory documents the file formats of the game data that this project reads. Every statement here must be backed by evidence recorded in [EVIDENCE_LOG.md](EVIDENCE_LOG.md).

## Rules

1. **Evidence first.** A field is documented only after it is observed in real files. Guesses go in the "Hypotheses" section of a format document, never in the field table.
2. **Confidence levels.** Every field carries one of:
   - `confirmed`: verified by differential testing or by at least two independent samples.
   - `observed`: seen in sample files, meaning not yet verified.
   - `hypothesis`: inferred, not verified.
3. **Reproducibility.** Record file name, size in bytes, SHA-256, and byte offsets for every sample. Do not rely on memory or screenshots.
4. **No original assets in the repository.** Do not commit game executables, archives, images, audio, or full dumps. Short hex excerpts (at most 64 bytes) are acceptable as documentation. Test fixtures must be synthetic and generated by this project.
5. **No protected code.** Executables are protected by an executable wrapper and are out of scope. Formats are derived from data files and observed behavior only.
6. **Clean-room discipline.** Community documentation may be used to cross-check field meaning. Do not copy code from repositories without an explicit license.
7. **Test coupling.** Each `confirmed` structure should have a parser unit test that uses a synthetic fixture matching the documented layout.

## Workflow

1. Collect samples and record them in `EVIDENCE_LOG.md`.
2. Inspect headers and structure with `xxd`, `hexdump`, or a script.
3. Form a hypothesis and write it down.
4. Verify by differential testing: change one value in game, save, and compare before and after.
5. Promote the field from `hypothesis` to `observed` or `confirmed` and cite the evidence ID.
6. Add or update parser code and its synthetic test.
7. Update the index above.
